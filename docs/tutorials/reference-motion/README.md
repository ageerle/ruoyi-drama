# 从参考视频复刻动作

导演工作台为预览功能，尚未正式发布。本次按用户提供的参考片，复刻闪身步、浪子踢球、狗熊哆嗦毛三段动作，并保留原片中的近景讲解与全身示范切换。原片约 32.37 秒；工程为 33 秒，末尾补约 0.63 秒收势停留。

## 在当前项目查看

进入流程设计器，打开「参考视频动作复刻 · 闪身步与勾踢」导演节点。时间轴上的动作标记可以跳到闪身步、浪子踢球、狗熊哆嗦毛和最后一轮收势。人物有 390 个可编辑关键帧；基础动作设为站立，具体表演记录在关节姿态、位置和机位中。

先播放一次，再选中人物，在「关节姿态」修改当前帧。骨盆负责腰胯转动，躯干负责上身倾侧；左右肩带负责肩部提落，手腕负责抬掌与放松，脚踝负责脚尖与脚掌方向。勾踢应一起检查大腿、膝盖和脚踝，不能只抬高整个人物。修改会自动记录关键帧，Ctrl+Z 撤销，Ctrl+S 保存。

## 用其他参考视频制作

1. 在空的导演节点点击「参考视频动作」。选择本地视频；已有当前站点素材，也可以展开对应入口填入视频地址。
2. 填写开始与结束秒数。一次解析 2–60 秒，文件上限 200MB；建议使用固定机位、单人、全身清晰的视频。
3. 点击「解析参考动作」。MediaPipe 模型和运行文件由当前站点提供，姿态推理在本机浏览器运行，视频不上传。每秒提取 12 次，转换成 24 fps 白模工程。
4. 识别完成后点击「应用为导演工程」，在工作台检查表演并修正。当前有未保存工程时，会先导出备份。
5. 在「走位」按需要启用「自动脚底贴地」和「关节球面插值」。前者每帧让最低脚底接触舞台，人物位置 Y 用于主动腾空；后者避免转体时跨过 ±180 度产生反向旋转。
6. 设置机位并「导出白模视频」。输出使用工作台同一份姿态计算，24 fps；导出后先回放，再使用白模作为后续制作参考。

姿态提取是单目估计，侧转、遮挡和低清会造成误差。它没有脚底水平锁定、手指抓握或真实碰撞系统；贴地只修正垂直接触，横向滑步仍需手动调整。近景里隐藏的腿不会当成真实识别结果。捕捉工程还会按白模头部尺寸，对危险的手臂姿态做小幅肩带修正，修正保留为可编辑关键帧。

## 本次动作依据

| 参考时间 | 动作 | 检查重点 |
| --- | --- | --- |
| 2.3–9.3 秒 | 四次左右闪身，回到并步站姿 | 侧步与倾身先后、手臂随摆、回中停顿 |
| 12–16.3 秒 | 张臂平衡，交叉步，向后勾踢，交替收回 | 支撑腿屈膝、踢腿弯膝、脚尖方向、摆臂平衡 |
| 24.7–28.5 秒 | 左右侧摆、交叉步、双臂举落、耸肩抖身 | 骨盆与胸部分开旋转、肩带提落、左右转换 |
| 28.5–30.4 秒 | 近景重复摆身动作 | 上身节奏和镜头切换，隐藏足部不作精确判断 |
| 30.4–32.37 秒 | 全身最后一轮，回中收势 | 双脚回中、手臂放下与结束状态 |

本次提取 389 次采样，其中 389 次检测到人物。复刻工程的 792 帧检查了脚底与手、肘对头部的几何距离；这不等于全身碰撞验证，也不等于动作相似度或完整人工视听验收。实际结果、项目回读与导出信息保存在产物目录的验证记录中。

产物目录为 `output/reference-motion/`，包括可编辑工程、白模 MP4、原片与复刻对照页以及验证记录。`extract.py` 是本地提取脚本，`design.ts` 使用项目共享的转换器制作本次工程，便于复查和重复生成。

## 将白模用于写实视频

在导演工作台先导出白模视频，回到项目的「分镜确认」，为当前镜头选择支持视频参考的模型。展开「动作视频参考（白模 / 实拍）」，上传 MP4 或 MOV，再点击「用于本镜」并保存镜头。上传只将参考保存在当前项目；点击「生成视频」时才会随本镜导演稿提交给生成模型。已保存的参考可在同项目其他镜头使用，移出本镜不会删除原片。

当前上传限制为 30MB，支持 H.264 / H.265、24–60 fps、2–30 秒的视频。Seedance 2.0 参考模型最多选择 3 条，合计不超过 15 秒；2.5 参考模型最多 10 条，合计不超过 30 秒。超过时长应在上传前裁出需要的动作段，不能把 33 秒完整白模直接用于 2.0 Mini。

导演稿中的 `@video1`、`@video2` 按本镜选择顺序指向动作片。写清成年演员的外观、服装、空间、摄影与声音，并说明白模提供哪些动作依据。首帧仍为可选：纯动作参考可以直接生成，不必先生成角色图片。模型输出仍需逐段回放，尤其检查支撑脚、换腿、关节遮挡和结束姿态，不能将参考传输成功视为动作复刻验收。

本次写实样片单独保存为「身法练习｜白模转写实样片」项目。12 秒白模参考依次选取闪身、勾踢、摆身各 4 秒，原完整白模与已有项目保留。`real_video.py` 通过正常登录、项目审阅和视频任务接口提交，记录请求 UUID 与任务回执；未知提交结果不会自动重发。执行顺序为 `prepare`、`attach`、`submit`、`status`，已有工作目录会复用记录；变更候选需使用独立目录，不能覆盖已提交记录。
