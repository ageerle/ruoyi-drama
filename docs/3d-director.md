# 3D 导演工作台（预览版）

这是流程设计器中的白模预演功能，还未正式发布。它用于先确定人物、道具的位置，排练动作和摄影机运动，再导出一段可检查的白模视频。当前版本的白模是程序生成的关节模型，没有外部人体模型下载依赖。

进入任意短剧项目的流程设计器，点击左侧「3D 导演」，或在画布空白处右键添加同名节点。新节点打开一个空场景，只有默认摄影机。以后点击节点的「编辑节点」或双击节点，可重新进入同一份工程。

动作编排、关节姿态和双人练习见 [动作设计操作参考](3d-director-actions.md)，工作台右上角也可直接查看。

## 从空场景开始

1. 左侧添加人物白模、方块道具、墙体、门框、城门城墙或大炮。场景列表可以选择、隐藏和锁定对象；对象行或视口右键可以添加对象、创建副本、删除对象和切换俯视布局。
2. 选中白模后，右侧设置名称、颜色、位置、朝向和尺寸。位置单位为米，朝向单位为度，人物默认约 1.8 米高。也可以在视口用「移动 / 旋转 / 缩放」操纵轴调整；人物旋转只开放竖直轴。锁定对象后，位置、动作和尺寸不会被修改。
3. 在时间轴第 0 帧设置起点和「行走」动作，再移到另一个时刻，修改位置并选择「站立」或「招手」。坐标和基础动作编辑会记录当前时刻的关键帧；「动作编排」中可另设带起止、速度、幅度和过渡的动作片段，「关节姿态」可微调 10 个身体部位。相邻位置和姿态可匀速、缓入缓出或保持后切换；「沿路线自动朝向」可随移动方向转身，白模不会自动避障。
4. 点击「摄影机」，设置机位坐标、拍摄目标、FOV 和画面倾斜。分别在两个时刻设定不同的机位/目标，可设计推拉和绕拍。「瞄准场景对象」取当前时刻的位置；「持续跟随目标」可实时跟随视线，或同时按固定世界坐标偏移移动机位。也可先旋转编辑视口，再点击「当前视角设为机位」。右下角监看窗口显示实际导出构图。
5. 点击播放，检查动作与运镜；暂停后继续调整。时间轴可拖动、输入精确帧号或直接点击轨道关键帧。右侧可删除、复制或移动当前关键帧；时间轴支持拖动菱形移动，Alt 拖动复制，起始的第 0 帧保留。片段长度为 2–60 秒，固定 24 fps，支持横屏和竖屏。缩短片段时会保留新结束时刻的插值姿态。

空场景可点击「载入炮轰城门示例」。两名土匪在城外架炮，两名官军站在城墙上，七秒开炮，半秒后命中门洞上方，碎砖落地，守军伏身，土匪随后推进。选中大炮，在「命中目标」中选择城门，再设置发射时刻；炮身后坐由位置关键帧控制。城门受击是可回放的简化破坏预演，碎砖和烟尘随时间轴计算，拖回命中前会恢复墙体。它没有真实物理模拟，不能用于结构或武器性能计算。

「载入双人走位示例」只在空场景启用，演示来客穿过门框、停止招手和摄影机靠近的调度，载入后每个对象和关键帧仍可编辑。它不会在创建节点时自动填入。「清空场景」、对象删除、参数编辑均可撤销；工具栏支持撤销和重做，非输入区域也可用 Ctrl+Z、Ctrl+Shift+Z、Ctrl+D、Delete、空格和 Ctrl+S。

## 保存和导出

工程自动保存到当前项目，也可点击「保存工程」。返回流程画布前会等待保存成功；读取失败时不会以空工程覆盖原工程。后端沿用项目所有者校验，按版本拒绝过期写入。保存失败会保留本地修改并显示错误，点击「备份并重新加载」会先下载当前 JSON，再读取服务端版本。关闭或刷新仍有未保存修改的网页会触发浏览器提示。

「导出工程」保存可迁移的 JSON，包括白模、动作、路线、机位和画幅；「导入工程」读取独立导演工程 JSON。JSON 不包含登录凭据或付费媒体任务。复制流程画布中的导演节点后，首次打开会复制源工程到新的工程编号，之后独立编辑。整体画布 JSON 只含导演工程引用，跨项目迁移 3D 场景时应另外导出和导入导演工程。

「导出当前帧」按摄影机构图输出 PNG。「导出白模视频」在浏览器中逐帧编码 H.264 MP4，横屏为 1280×720，竖屏为 720×1280，固定 24 fps，没有声音、网格、路线和操纵轴。编码完成后自动下载，并出现视频回放窗口。此操作需要浏览器支持 H.264 WebCodecs；不提交 AI 生成任务，不消耗媒体模型额度。可取消正在进行的视频导出。

回放窗口的「保存为本项目动作参考」通过现有上传接口保存实际导出的 MP4。回到分镜，展开「动作视频参考」，刷新列表并选择这条白模，保存镜头后再点击「生成视频」。上传只保存素材，生成才提交模型任务。参考接口接收 2–30 秒、单文件小于 30MB 的视频；具体可选条数和总时长由当前分镜模型校验。

## 当前范围与实现

当前预览版包含单摄影机、多人物/道具、十二种关节动作、独立动作片段、关节姿态微调、三种插值、自动朝向和目标跟随、基础空间变换、城门与炮击预演、俯视布局、监看、保存回读和 PNG/MP4/JSON 导出。导出的白模可经分镜动作参考接口参与视频生成。它尚未包含 GLB 导入、IK 末端控制、曲线编辑、多镜头剪辑、碰撞避障和多人协同。导演节点本身不会作为成片加入合成，须先在分镜生成视频。

三维模块通过异步组件进入，普通流程画布不会加载 Three.js 视口；视频编码模块只在导出时加载。场景文档和关键帧计算在 `src/utils/dramaDirector.ts`，视口/关节白模在 `components/director/directorScene.ts` 和 `DirectorViewport.vue`，文档保存与历史由 `useDirectorDocument.ts` 管理。后端在 ruoyi-ai 的 `ShortDramaDirectorService` 保存原子 JSON 文件，默认目录为运行工作目录下 `data/short-drama-directors/<项目编号>/<工程编号>.json`。部署时应把该目录与其他业务持久数据一起挂载和备份；当前采用单进程版本校验，不提供分布式多实例写入协调。

前端使用 npm 注册表中的 Three.js（MIT）和 Mediabunny（MPL-2.0），编码库保持上游原样；许可证和上游源码入口保存在 `public/third-party/`，没有复制开源导演台中的第三方人体资产。LibTV 的操作调研见已有的 `libtv-3d-director-research.md`。

## 首版验证记录

2026-10-04 在 Edge 的「雨夜的修鞋摊｜流程设计器教程」项目中从空场景建立了「白模调度练习 · 走位与运镜」，保留原来的七个制作节点。实际验证添加白模和道具、坐标/朝向/尺寸/颜色编辑、三维操纵轴拖动、关键帧、播放、俯视、隐藏、锁定、副本与撤销，以及关闭后和新页面中的工程恢复。导出的 8 秒 MP4 经 ffprobe 检查为 H.264、1280×720、24 fps、192 帧，完整 FFmpeg 解码通过，Edge 回放时间有实际推进且无视频解码错误；这不是复杂动作或影视表演质量的验收。前端构建和 13 项相关测试、后端权限/持久化/版本冲突等 6 项测试通过。

## 动作编辑扩展验证

同日在上述项目新建「动作设计练习 · 双人回应」，保留首版工程。实际验证动作片段新增、起止/速度/幅度/过渡调整、顺序复制、删除，关节数值编辑与旋转环拖动，姿态复制到其他帧和左右镜像，精确移动及拖动关键帧，摄影机实时注视与固定偏移跟随，保存后关闭并重新打开。前端构建与 21 项相关测试、后端 8 项权限/格式/持久化/版本测试通过。新增的动作、关节和跟随字段沿用 schema 1 的可选扩展，首版文档不需迁移。

十二秒示例导出为 H.264、1280×720、24 fps、288 帧，完整 FFmpeg 解码通过，Edge 播放到结束，视频解码错误为空。真实界面截图、JSON 工程、视频和核验记录位于本地 `output/3d-director-v2/`。这些验证覆盖功能、数据保存和视频回放，不表示已完成逐帧的复杂表演或精确接触验收。
