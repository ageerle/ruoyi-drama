# ruoyi-drama

在线演示：[code.ruoyiai.chat](https://code.ruoyiai.chat/)

ruoyi-drama 是基于 Vue 3、TypeScript 和 Vite 的短剧工作台，配套 ruoyi-ai 后端使用。前端负责剧本编辑、素材审阅和任务进度展示，登录权限、模型调用、素材存储和视频合成由后端处理。

制作流程分为想法、剧本、资产和分镜四步。每一步审阅后再进入下一步，角色、场景和道具可以在项目里反复使用。

工作台操作与制作维护规范见[项目文档索引](docs/README.md)。

第一步的[原始创作输入](docs/creative-idea-persistence.md)随项目保存，刷新或切换项目后会回显；已有项目可单独“保存想法”，后续剧本修改保留这份输入。

有对白的角色可在资产页生成或上传样音并提前绑定；单镜、批量和重生成视频会按实际发言人带入固定样音。操作与接口见[角色声音与视频生成](docs/character-voices.md)。

## 本地运行

先启动 ruoyi-ai 后端，完成数据库、缓存和模型配置。前端默认连接本机 6039 端口。

在当前项目目录执行：

```bash
npm install
npm run dev
```

开发页面地址以 Vite 启动输出为准。连接配置放在 `.env.development`：

```dotenv
VITE_API_URL=/dev-api
VITE_API_PROXY_TARGET=http://127.0.0.1:6039
VITE_CLIENT_ID=后台配置的客户端ID
```

`VITE_API_URL` 使用相对路径，开发请求通过 Vite 代理转发。切换后台时修改 `VITE_API_PROXY_TARGET`，客户端 ID 与后台保持一致。登录使用后台已有账号。

## 模型与合成环境

在后台模型管理中配置写作、图片、视频和音频模型。前端按用途读取可用模型及默认优先级，API Key 保存在后台。使用 Atlas Cloud 时，在工作台头像菜单打开「Key 配置」，填写密钥并保存，系统会更新 Atlas 提供商下的模型配置；账号需要模型编辑权限。

剧本、资产分析和分镜默认使用 `deepseek-ai/deepseek-v4.1-flash`，关闭思考模式。三步共用文字生成参数和流式读取逻辑。模型名称按实际型号填写，默认优先级由后台模型管理维护。豆包 Seed 2.1 Pro 与 Evolving 是不同型号。

视频合成需要后端安装 FFmpeg 和 ffprobe，并支持 `libx264`、`aac` 编码器。Windows 可在 ruoyi-ai 仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\docs\script\install-ffmpeg-windows.ps1
```

脚本通过 winget 安装 FFmpeg，配置 `FFMPEG_PATH`、`FFPROBE_PATH` 和 `Path`。安装后重启 IDE 与后端服务，让进程读取新的环境变量。后端 Docker 镜像已包含 FFmpeg。

## 短剧工作台，从对话到镜头完成

这次整理 RuoYi Drama 的短剧工作台，用现有项目展示各个功能。做片时需要来回改剧本、选形象、听声音、检查镜头，所以这些内容都留在项目里，随时可以回到对应步骤继续处理。

工作台分四步：输入想法、剧本审阅、资产配置、分镜确认。视频生成和成片合成都在第四步完成。下面按使用顺序讲，截图保留完整桌面页面和操作入口。

第二步可以编辑项目名称、剧本名称、风格 / 基调、剧情大纲和剧本正文。这个案例的基调是中式志怪、真人电影写实，后面的资产制作沿用这一设定。已有剧本也可以在正文框里直接编辑。

### 05 分析资产：整理角色、场景和道具

资产分析把剧本里需要用到的人物、地点和道具整理成项目档案。先检查提取是否完整，再做图片，避免每个镜头都重新描述一遍。角色、场景和道具分别有自己的页签，「重新分析」用于再次梳理剧本，「一键生成」用于补齐缺少的资产图片。

![资产配置：角色库可以搜索、筛选，并查看已有形象数量。](docs/demo/short-drama-workflow/11.jpg)

### 09 生成分镜：按内容安排镜头，再自行调整

资产确认后点击「生成分镜」，工作台进入第四步。首次生成前可以在资产页选择分镜方式；已经有分镜的项目直接进入镜头编辑。分镜数量要随动作与对白安排，简单内容用少量镜头，内容多的场次再拆开。预计时长帮助判断节奏，制作时仍可以调整。

第四步左侧按场次列出镜头，可以筛选拍摄场次，也可以用上一镜、下一镜切换。右侧编辑标题和视频提示词。「新增镜头」用于补段落，「删除镜头」用于删去多余镜头，镜号会随之整理。

### 11 镜头完成：播放、检查和单独下载

任务返回后，点击「播放视频」查看结果，播放器中可以下载该镜头。检查对白是否完整、声音是否对应人物、动作与道具位置是否接得上。需要改一镜时，回到该镜修改提示词并保存，再决定是否重新生成。

### 12 合成与下载：选择完成的镜头，接成一版

第四步顶部的「成片合成」用于选择已经完成的镜头，设置转场、画幅和水印。合成完成后显示状态与成片时长，点击「下载合成视频」即可保存。需要先看一个片段，就只选择那几镜。

这一轮工作台更新，把剧本修改、资产版本、声音绑定、分镜增删和视频结果放到了各自的步骤里。做片时发现问题，可以找到对应内容继续改，选好的图片、声音和已有镜头也有地方保留。

## 剧本打磨与风格

在剧本审阅中直接编辑正文，或填写修改意见后打磨。人物关系、时代背景和资源条件确认后，再推进资产与分镜；修改正文后需要重新检查旧分镜。

项目的画面方向在剧本审阅中的「风格 / 基调」维护。分镜方式来自后台启用的导演技能，保存绑定后参与后续生成。开发时沿用后端的技能加载和内容审阅流程，让同一套规则覆盖新的生成入口。修订提示词时保留已批准的图片、素材任务编号和连续性字段。

## 部署与数据

```bash
npm run build
```

前端产物在 `dist/`。生产接口前缀由 `.env.production` 配置，默认 `/prod-api`；Nginx 将该路径转发到后端。仓库中的 `nginx.conf` 包含页面路由回退、较长的接口等待时间，以及关闭代理缓冲的配置，部署时按后台位置调整。

数据库与后端本地文件一起备份。角色、分镜和任务关联保存在数据库；本地素材、声音和技能内容使用以下目录：

| 数据 | 后端运行目录 |
| --- | --- |
| 上传及导入素材 | `data/short-drama-materials/` |
| 声音与音乐任务 | `data/short-drama-sounds/` |
| 制作技能及历史版本 | `data/short-drama-skills/` |
| 本地成片 | 默认 `logs/short-drama-compositions/`，可通过 `short-drama.composition.local-output-directory` 修改 |

迁移服务时同步这些目录及实际使用的对象存储配置，避免项目记录还在、素材文件丢失。
